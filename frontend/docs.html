Auth System
API Reference

A self-hosted license management API. Create apps, generate & verify license keys, enforce HWID locking, and manage users — all over a simple REST interface secured by Bearer token auth.

✓ Self-hosted ✓ Bearer Auth ✓ HWID Locking ✓ Rate Limited ✓ Atomic Writes
Overview
Introduction

Auth System is a lightweight Flask-based REST API for managing software licenses. It's designed for tool developers who want to protect their software with license keys, hardware ID locking, and version enforcement — without relying on a third-party service.

The system consists of three components:

server.py — The Flask REST API. All license logic lives here.
bot.py — An optional Discord bot that wraps every API endpoint in slash commands.
dashboard.html — A browser-based admin + user portal with no dependencies beyond the API.

Base URL: All endpoints are prefixed with /Auth. For example: http://your-server:5000/Auth/create-app
Getting Started
Quick Start

Get running in under 5 minutes.

1

Clone & install

Clone the repo and install Python dependencies.

2

Configure config.yaml

Set your authtoken, port, and base_url. This token is the master key for all API calls.

3

Start the server

Run python server.py. The API is now live at http://0.0.0.0:{port}/Auth.

4

Create your first app

POST to /Auth/create-app with your app name and version. You'll get back an app_id and app_secret — save these.

5

Generate & assign a license

Generate keys with /Auth/gen-license, then activate one with /Auth/assign-license.

6

Verify from your tool

Call /Auth/verify-license on startup from your software. Pass the license key, app secret, HWID, and version. Done.

bash — install
pip install flask pyyaml pytz tls-client discord.py aiohttp
bash — run
python server.py
# Server starts on http://0.0.0.0:5000/Auth

Security
Authentication

Every endpoint requires a Bearer token in the Authorization header. The token is set via authtoken in config.yaml.

bash — header format
Authorization: Bearer your-secret-token-here
curl — authenticated request
curl -H "Authorization: Bearer your-token" \
     -H "Content-Type: application/json" \
     http://localhost:5000/Auth/check
Keep your token secret. Anyone with it has full control over all apps and licenses. Never commit it to version control — use environment variables or keep config.yaml in your .gitignore.

POST
/Auth/ban-license
Permanently remove a license. The key is deleted from active licenses — it cannot be recovered.
curl example
bash
curl -X POST http://localhost:5000/Auth/ban-license \
  -H "Authorization: Bearer your-token" \
  -H "Content-Type: application/json" \
  -d '{"license_key":"MyTool-M-aB3dEf7h"}'
Irreversible. There is no undo. The key is deleted — the customer will need a new license if banned by mistake.
POST
/Auth/reset-hwid
Clear the hardware ID binding on a license. The user's HWID will be re-captured on their next verification call. If the user doesn't match the stored user, license sharing is detected and the license is auto-banned.
curl example
bash
curl -X POST http://localhost:5000/Auth/reset-hwid \
  -H "Authorization: Bearer your-token" \
  -H "Content-Type: application/json" \
  -d '{"license_key":"MyTool-M-aB3dEf7h","user":"123456789"}'
200HWID reset — will re-bind on next verify call
403User mismatch detected — license sharing — license auto-banned

Integration
Python Example

Paste this into your tool's startup code. It calls verify-license and exits if the key is invalid, expired, or the version is outdated.

python — verify on startup
import sys, uuid, requests

# ── Config ────────────────────────────────────────
SERVER     = "http://your-server:5000/Auth"
APP_NAME   = "MyTool"
APP_SECRET = "aB3dEf7hIj2kLmNo"  # from create-app
VERSION    = "1.0.0"
API_TOKEN  = "your-bearer-token"

def get_hwid() -> str:
    return str(uuid.UUID(int=uuid.getnode()))

def verify_license(license_key: str) -> bool:
    try:
        r = requests.get(
            f"{SERVER}/verify-license",
            params={
                "license_key": license_key,
                "app_name":    APP_NAME,
                "app_secret":  APP_SECRET,
                "hwid":        get_hwid(),
                "version":     VERSION,
            },
            headers={"Authorization": f"Bearer {API_TOKEN}"},
            timeout=10,
        )
        if r.status_code == 200:
            data = r.json()
            print(f"✓ License valid — expires {data['expiry']}")
            return True
        elif r.status_code == 426:
            link = r.json().get("link", "unknown")
            print(f"✗ Outdated version. Download: {link}")
        elif r.status_code == 403:
            print("✗", r.json().get("error"))
        else:
            print("✗", r.json().get("error", "Unknown error"))
    except requests.RequestException as e:
        print(f"✗ Could not reach license server: {e}")
    return False

# ── Startup check ─────────────────────────────────
key = input("Enter license key: ").strip()
if not verify_license(key):
    sys.exit(1)

Rate Limits

Limits are enforced per IP address over a rolling 60-second window.

EndpointLimitWindow
/verify-license60 requests60 seconds
/get-license30 requests60 seconds
/assign-license, /update-*20 requests60 seconds
/create-app20 requests60 seconds
/gen-license10 requests60 seconds
/reset-hwid, /cleanup10 requests60 seconds
429 Too Many Requests is returned when a limit is hit. The client should back off and retry after 60 seconds.
