Getting Started
Everything you need to start using the API
1

Run the server

Start server.py — it runs on 0.0.0.0 at the port in your config.yaml.

bash
python server.py
2

All requests need a Bearer token

Set the Authorization header on every request using the token from config.yaml.

http
Authorization: Bearer your_token_here
3

Create an app, generate licenses, verify

The flow is: Create App → Generate Licenses → Assign License → Verify License from your client software.

Authentication
Bearer token required on all endpoints

Every request must include the Authorization header. The token is compared using constant-time comparison to prevent timing attacks.

http
Authorization: Bearer YOUR_TOKEN
🚫Requests without a valid token always return HTTP 401 {"error": "Unauthorized"}.

Example Request
python
import requests

r = requests.post('http://localhost:5000/Auth/create-app',
    headers={'Authorization': 'Bearer TOKEN'},
    json={
        'app_name': 'MyApp',
        'version':  '1.0.0',
        'link':     'https://download.example.com/MyApp.exe'
    }
)
print(r.json())
# Save app_secret — you'll need it for verify-license!
⚠️Save the app_secret from the response. It is shown only once and is required for verify-license calls.

GET /Auth/verify-license Verify a license from client software ▼

This is the endpoint your client app calls at startup to validate the user's license. Parameters are passed as query strings.

Query Parameters
ParamTypeDescription

app_secretstring requiredFrom create-app response

versionstring requiredClient app version
Response Codes
200 Valid 401 Bad secret 403 Expired/HWID 404 Not found 426 Old version
Response 200
json

  "message": "License valid",
  "expiry":  "2025-05-11 12:00:00",
  "hwid":    "abc123def"
}
Full Python Client Example
python
import requests, uuid

# Embed these in your compiled app — never expose publicly
API_URL    = "http://your-server.com/Auth/verify-license"
TOKEN      = "your_bearer_token"
APP_NAME   = "MyApp"
APP_SECRET = "aBcDeFgH12345678"
VERSION    = "1.0.0"

def get_hwid():
    return str(uuid.UUID(int=uuid.getnode()))

def verify_license(license_key: str) -> bool:
    r = requests.get(API_URL, params={
        "license_key": license_key,
        "app_name":    APP_NAME,
        "app_secret":  APP_SECRET,
        "hwid":        get_hwid(),
        "version":     VERSION,
    }, headers={"Authorization": f"Bearer {TOKEN}"})

    if r.status_code == 200:
        return True
    elif r.status_code == 426:
        link = r.json().get("link")
        print(f"Update required → {link}")
    else:
        print(r.json().get("error"))
    return False

# At startup:
key = input("Enter your license key: ")
if not verify_license(key):
    exit()
⚠️On first use, the HWID is bound automatically. A different device returns 403 HWID mismatch. Users must request an HWID reset from the admin.

Client Integration
How to embed license verification in your tool
💡Your tool (the software you sell) should call /Auth/verify-license at startup. Embed the app_secret, app_name, token, and your server URL directly in the compiled binary.
Status Code Handling
CodeMeaningWhat to do
200License validAllow access. Store expiry locally for offline grace period.
401Bad token / secretDeveloper config error — check your embedded token.
403Expired or HWID mismatchBlock access. Show specific message from response body.
404License not foundPrompt user to re-enter or contact support.
426Outdated versionAuto-open browser to link field in the response.
429Rate limitedRetry after 60 seconds.
GitHub Merge Guide
How to push the v2.0 improvements into your existing repo
💡Your existing repo is maybeninja/Authentication-System. These steps merge the improved files into it safely without losing history.
1

Clone your repo locally

If you don't have it already

bash
git clone https://github.com/maybeninja/Authentication-System.git
cd Authentication-System
2

Create a new branch for the update

Never push directly to main

bash
git checkout -b v2-improvements
3

Copy in the new files

Replace server.py, bot.py, panel.py — add frontend/ and requirements.txt

bash
# Copy the improved files into your repo folder:
# server.py          → replace existing
# bot.py             → replace existing
# panel.py           → replace existing
# requirements.txt   → replace or create
# frontend/dashboard.html → new folder + file

mkdir -p frontend
4

Add a .gitignore

Protect config.yaml and Database/ from being committed

bash
cat > .gitignore << EOF
config.yaml
Database/
__pycache__/
*.pyc
*.log
.env
EOF
🚫Your config.yaml contains your auth token and Discord bot token. Never commit it. The current repo already has it exposed — consider rotating those tokens.
5

Stage and commit everything

bash
git add server.py bot.py panel.py requirements.txt frontend/ .gitignore
git commit -m "feat: v2.0 — security, rate limiting, frontend dashboard"

# What this commit includes:
# ✓ Cryptographic key generation (secrets module)
# ✓ Per-IP rate limiting on all endpoints
# ✓ Atomic file writes — no corruption on crash
# ✓ Input sanitization — path traversal protection
# ✓ Constant-time token comparison
# ✓ /cleanup and /health endpoints
# ✓ Frontend dashboard (admin + user portal)
# ✓ Improved Discord bot with error handler
6

Push the branch to GitHub

bash
git push origin v2-improvements
7

Merge into main

Two options — pick one

Option A — Via GitHub UI (recommended)
steps
1. Go to github.com/maybeninja/Authentication-System
2. Click "Compare & pull request" on the v2-improvements branch
3. Add a title and description
4. Click "Merge pull request"
Option B — Via command line
bash
git checkout main
git merge v2-improvements
git push origin main
8

Tag the release

Optional but good practice

bash
git tag -a v2.0 -m "v2.0 — Security improvements + frontend dashboard"
git push origin v2.0
⚠️
Before you push: your current repo has config.yaml committed with real tokens in it. Go to your Discord Developer Portal and regenerate your bot token, and update authtoken in config.yaml to a new value. Then add .gitignore first so config.yaml never gets pushed again.
